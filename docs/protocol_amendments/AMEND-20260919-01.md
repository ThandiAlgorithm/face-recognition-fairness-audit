## Type

## Change

Change the frozen RetinaFace detector from the TensorFlow-backed `retina-face` package (serengil, 0.0.18) to a project-native PyTorch RetinaFace implementation (`src/retinaface/`), running the MobileNetV1 0.25 checkpoint directly rather than through a third-party wrapper package.

This was reached in two steps: first a switch to the PyPI package `face-detection` (elliottzheng, 1.0.5) as a working PyTorch proof of concept, then a further switch to the project-native implementation below once its architecture and checkpoint compatibility were independently verified. The PyPI-wrapper step is not the final state and should not be treated as the frozen implementation — the specification in this amendment is.

## Reason

The original TensorFlow choice was made without deliberately weighing it against available PyTorch implementations — `retina-face` was picked as the most common PyPI name for "RetinaFace," not because TensorFlow was a considered requirement. `configs/models.yaml`'s environment section otherwise centres on PyTorch, so the detector sitting on a separate TensorFlow stack was an inconsistency worth correcting.

The further move from the PyPI wrapper to a project-native implementation is so the exact architecture, checkpoint provenance, and inference settings (NMS, top_k, keep_top_k, resize) are fully specified and verifiable in this repository, rather than depending on an external package's internal, unaudited defaults.

## Effect (applies once this amendment is approved, not before)

- `configs/preprocessing.yaml`: `detector.implementation` changes to `project_native`, `detector.framework` to `pytorch`, `detector.backbone` to `mobilenet0.25`; `confidence_threshold`, `nms_threshold`, `top_k`, `keep_top_k`, and `resize` are explicitly frozen to the values in the Inference settings section above.
- `src/config.py`'s `validate_preprocessing()` guard changes to require `project_native` instead of `elliottzheng_pytorch`.
- `configs/models.yaml`: `checkpoints.retinaface` updated to record the project-native implementation and checkpoint provenance above; prior entries (the original TensorFlow package and the intermediate `face-detection` PyPI wrapper) are preserved under `superseded`, not deleted.
- No downstream table needs to be discarded or rebuilt because of this change specifically — no full-scale extraction has been run under any prior detector implementation.
