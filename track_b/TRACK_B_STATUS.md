# Track B — Facial Verification and Fairness Evaluation

## Status

**Branch:** `audit/lfw-verification-rz`

**Track:** B — Facial Recognition / Verification

**Primary benchmark:** Labeled Faces in the Wild (LFW)

**Current stage:** Evaluation infrastructure complete; official R0 evaluation waiting for project-aligned LFW crops.

---

## 1. Purpose

Track B evaluates facial verification performance and demographic disparities using a common evaluation framework.

The experimental sequence is:

1. R0 — pretrained ArcFace reference recognizer
2. M0 — project-trained baseline recognition model with no fairness mitigation
3. M1 — data-level mitigation
4. M2 — loss/sample reweighting mitigation
5. M3 — representation-level/adversarial mitigation
6. M4 — optional distribution-level mitigation if time permits

All models must be evaluated using the same LFW protocol, pair definitions, scoring rules, and fairness analysis.

## 3. Common Verification Protocol

The common protocol is frozen in:

`configs/track_b_verification.json`

The main rules are:

- use project-aligned face crops
- use the same preprocessing for all recognition models
- use L2-normalized embeddings
- use cosine similarity
- higher score means more similar
- use one global verification threshold
- do not use subgroup-specific thresholds
- select the threshold using View 1 train only
- freeze the threshold before evaluating View 1 test
- official fairness analysis is performed on View 1 test
- View 2 remains sealed

Threshold criterion:

`Maximum Youden J / maximum balanced accuracy`

## 8. Fairness Evaluation

Primary subgroup analyses include:

- gender
- derived race
- race × gender intersection
- later skin-tone / visual-condition analyses where Phase 1 measurements are available

Primary subgroup metrics include:

- TPR / TAR
- FMR / FPR
- FNMR / FNR
- accuracy
- balanced accuracy

For impostor fairness:

- primary FMR uses within-group impostor pairs
- cross-group impostor pairs are reported separately

One global verification threshold is used for every demographic group.

## 9. Statistical Analysis

The common statistics pipeline is prepared.

### Bootstrap confidence intervals

- confidence level: 95%
- bootstrap iterations: 2,000
- random seed: 2026
- stratified resampling by genuine/impostor pair type

Small subgroup samples are automatically flagged.

The current diagnostic test identified sparse groups including some Asian, Black, and intersectional groups. These results must therefore be interpreted with appropriate uncertainty and sample-size reporting.

### Paired model comparisons

Exact two-sided McNemar tests are prepared for:

- M0 vs M1
- M0 vs M2
- M0 vs M3

The comparison unit is the exact same LFW View 1 test pair.

## 12. M0–M3 Workflow

When model checkpoints/results become available from the training track:

### M0

Run the common evaluator with the ordinary unmitigated project model.

M0 becomes the primary project baseline.

### M1

Evaluate data-level mitigation using the same evaluation protocol.

### M2

Evaluate loss/sample reweighting using the same evaluation protocol.

### M3

Evaluate representation-level/adversarial mitigation using the same evaluation protocol.

For every mitigation:

- do not change the LFW pairs
- do not change preprocessing
- do not change the scoring definition
- do not create subgroup-specific thresholds
- keep View 2 sealed
- compare against M0 on the same View 1 test pairs
- report performance and fairness together
- use McNemar for paired decision comparisons
- report bootstrap confidence intervals
